# State-Based Actions (SBA) Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GameState::check_state_based_actions(&CardDb) -> Vec<MoveEvent>` — the CR 704 loop that finds creatures with lethal/zero toughness and moves them to the graveyard, performed simultaneously and repeated to fixpoint, so creatures actually die.

**Architecture:** A new module `magicbot-engine/src/sba.rs` holds the pure predicate that decides which battlefield creatures should be put into the graveyard (CR 704.5f zero-toughness, 704.5g lethal marked damage). `GameState::check_state_based_actions` runs the CR 704.3 loop: gather all objects meeting an SBA condition (computing current toughness via the existing `characteristics()`), perform them all as one batch by calling `move_object(id, Graveyard)` for each, then repeat until a pass finds nothing — returning every `MoveEvent` produced. This composes the three prior subsystems (characteristics for current toughness, move_object for the zone change, the MoveEvent vocabulary) into the first rule that makes the game progress. Life-total loss, +1/+1/-1/-1 annihilation, legend rule, regeneration replacement, deathtouch, planeswalker/saga/battle SBAs, and the trigger/priority interleave (CR 704.3's "then put triggers on the stack") are all DEFERRED.

**Tech Stack:** Rust 1.93+. No new deps.

**Source spec:** `prior-art/rules-core.md` §704 (the SBA list + 704.3 loop timing + 704.4 "ignore mid-resolution transients"), `prior-art/conformance-cases.md` section B (B1 fixpoint, B2 zero-toughness, B4 ignore-transient — partial). Bridges `state.rs`, `object.rs`, `events.rs`, `layers.rs`, `carddb.rs`.

## Global Constraints

- **Rust edition 2021**, toolchain `1.93+`.
- **Current toughness comes from `characteristics()`**, never from printed/base values directly — an SBA must see counters and anthem effects (a 1/1 with a -1/-1 counter is 0/0 and dies; a 0/0-base creature under an anthem survives). Reuse, do not reimplement P/T math.
- **SBAs are performed SIMULTANEOUSLY as one batch, then re-checked to fixpoint** (CR 704.3): one pass gathers ALL objects currently meeting a condition, performs them all, then loops; it does not perform one, re-evaluate, perform the next. The loop terminates when a pass finds nothing.
- **The death move is `move_object(id, Graveyard)`** — reuse the move pipeline (CR 400.7 new-object / drop-state is already correct there). Do not hand-roll the zone change.
- **Only the two creature-death SBAs** in this slice: 704.5f (toughness ≤ 0 → graveyard) and 704.5g (marked damage ≥ toughness, toughness > 0 → graveyard). Everything else in 704.5 is DEFERRED.
- **No triggers, no priority, no regeneration** — `check_state_based_actions` returns the `MoveEvent`s but nothing consumes them for triggers yet (deferred to the priority/stack plan).
- **Zero-toughness uses `≤ 0`; lethal-damage uses `marked_damage >= toughness` with `toughness > 0`** (a 0-toughness creature dies by 704.5f, not 704.5g — avoid double-classifying).
- **TDD**; `cargo test` + `cargo clippy --all-targets -- -D warnings` clean after every task.

```rust
/// Whether a creature should be put into its owner's graveyard by a state-based
/// action this slice models: CR 704.5f (toughness <= 0) or CR 704.5g (marked
/// damage >= toughness, for toughness > 0). Noncreatures never match.
pub fn creature_dies_to_sba(current: &layers::Chars, marked_damage: u32) -> bool {
    if !current.types.is_creature() {
        return false;
    }
    let pt = match current.pt {
        Some(pt) => pt,
        None => return false,
    };
    if pt.toughness <= 0 {
        // CR 704.5f
        return true;
    }
    // CR 704.5g: toughness > 0 here; lethal if marked damage meets/exceeds it.
    marked_damage >= pt.toughness as u32
}
```

**Files:**
- Modify: `magicbot-engine/src/state.rs`

**Interfaces:**
- Consumes: `characteristics()` (current P/T), `Object::marked_damage()`, `sba::creature_dies_to_sba`, `move_object`, `events::MoveEvent`.
- Produces: `impl GameState { pub fn check_state_based_actions(&mut self, db: &CardDb) -> Vec<MoveEvent> }` — the CR 704.3 loop:
  1. loop: scan all battlefield objects; for each, compute `characteristics()` and read `marked_damage()`; collect the ids for which `creature_dies_to_sba` is true (a single simultaneous batch);
  2. if the batch is empty, break;
  3. for each id in the batch, `move_object(id, Graveyard)` and collect the `MoveEvent`s;
  4. repeat (a fresh creature may now be lethal — e.g. its toughness depended on a creature that just died; fixpoint).
  Returns all `MoveEvent`s across all passes.

Add to `impl GameState` in `magicbot-engine/src/state.rs`:

```rust
    /// CR 704.3 state-based-action loop (this slice: creature death only).
    /// Performs all currently-applicable SBAs simultaneously as a batch, then
    /// repeats until a pass finds none. Returns every MoveEvent produced.
    /// Triggers/priority interleave and the rest of the 704.5 list are deferred.
    pub fn check_state_based_actions(
        &mut self,
        db: &crate::carddb::CardDb,
    ) -> Vec<crate::events::MoveEvent> {
        let mut events = Vec::new();
        loop {
            // Gather one simultaneous batch of doomed creatures.
            let mut doomed: Vec<ObjectId> = Vec::new();
            for (id, obj) in self.objects.iter() {
                if obj.zone() != crate::object::Zone::Battlefield {
                    continue;
                }
                let marked = obj.marked_damage();
                if let Some(chars) = self.characteristics(*id, db) {
                    if crate::sba::creature_dies_to_sba(&chars, marked) {
                        doomed.push(*id);
                    }
                }
            }
            if doomed.is_empty() {
                break;
            }
            // Perform them (move to graveyard). move_object mints new ids; the
            // doomed ids were gathered before any move, so no id is stale within
            // this batch (each id still refers to its battlefield object until
            // its own move).
            for id in doomed {
                if let Some(ev) = self.move_object(id, crate::object::Zone::Graveyard) {
                    events.push(ev);
                }
            }
        }
        events
    }
```

NOTE: gathering the whole batch before performing any move is what makes the batch "simultaneous" (CR 704.3). Because `characteristics()` borrows `self` immutably and `move_object` borrows mutably, the two phases are separated into a gather pass (immutable) then a perform pass (mutable) — this also satisfies the borrow checker. Each gathered id is still valid at the moment its own `move_object` runs (moving object A does not change object B's id).

```rust
// State-based actions composed with the full engine: SBA must read CURRENT
// (layer-computed) toughness, use the move pipeline, and honor CoW fork.
use magicbot_engine::carddb::sample_pool;
use magicbot_engine::ids::PlayerId;
use magicbot_engine::object::Zone;
use magicbot_engine::state::GameState;

#[test]
fn anthem_saves_a_creature_from_lethal_then_removal_kills_it() {
    // Bears 2/2 with 2 marked damage would die, but a +1/+1 anthem makes it 3/3
    // (3 toughness > 2 damage) -> survives. SBA reads COMPUTED toughness.
    let db = sample_pool();
    let mut s = GameState::new(2, 0);
    let bears = s.create_object(PlayerId(0), Zone::Battlefield, 1);
    let anthem = s.create_object(PlayerId(0), Zone::Battlefield, 3);
    s.get_mut(bears).unwrap().set_controller(Some(PlayerId(0)));
    s.get_mut(anthem).unwrap().set_controller(Some(PlayerId(0)));
    s.get_mut(bears).unwrap().mark_damage(2);

    // With the anthem, the bears are 3/3 and survive 2 damage.
    let events = s.check_state_based_actions(&db);
    assert!(events.is_empty(), "anthem keeps the bears alive");
    assert_eq!(s.battlefield_len(), 2);

    // Remove the anthem; now the bears are 2/2 with 2 damage -> dies on next check.
    // (Use the move pipeline to send the anthem to the graveyard.)
    let _ = s.move_object(anthem, Zone::Graveyard);
    let events2 = s.check_state_based_actions(&db);
    assert_eq!(events2.len(), 1, "bears now lethal without the anthem");
    // Only the (new) graveyard objects remain off the battlefield.
    assert_eq!(s.battlefield_len(), 0);
}

#[test]
fn sba_on_a_fork_does_not_disturb_parent() {
    let db = sample_pool();
    let mut parent = GameState::new(2, 0);
    let bears = parent.create_object(PlayerId(0), Zone::Battlefield, 1);
    parent.get_mut(bears).unwrap().set_controller(Some(PlayerId(0)));
    parent.get_mut(bears).unwrap().mark_damage(2);

    // In a fork, run SBA -> the bears die there.
    let mut child = parent.fork();
    let events = child.check_state_based_actions(&db);
    assert_eq!(events.len(), 1);
    assert_eq!(child.battlefield_len(), 0);

    // Parent is untouched: the bears are still on the battlefield (with their damage).
    assert_eq!(parent.battlefield_len(), 1);
    assert!(parent.get(bears).is_some());
}
```

## Out of scope for this plan (deferred to later plans)

1. **The rest of the CR 704.5 list:** life ≤ 0 loss (704.5a), draw-from-empty (704.5b), poison (704.5c), token cease-to-exist (704.5d), +1/+1 & -1/-1 annihilation (704.5q), legend rule (704.5j), planeswalker loyalty 0 (704.5i), Aura/Equipment attachment SBAs (704.5m/n), saga/battle, etc.
2. **Regeneration & indestructible & deathtouch** — 704.5g says regen CAN replace destruction, 704.5f cannot; this slice has no replacement effects and no indestructible/deathtouch, so a lethal creature simply dies.
3. **The trigger/priority interleave** — CR 704.3 says after SBAs, put triggered abilities on the stack, then re-check. This slice's loop only re-checks SBAs; nothing gathers triggers off the returned `MoveEvent`s yet (the priority/stack plan consumes them).
4. **704.4 mid-resolution transient immunity** — there is no spell resolution yet, so the "SBAs ignore transient 0-toughness during resolution" rule is not yet exercisable; the predicate is correct for the steady-state checks this slice runs.
5. **704.7 single-replacement for same-result SBAs and 704.8 LKI-before-SBA** — need replacement effects / LKI (deferred).
6. **Damage clearing at cleanup** (`clear_damage` exists but no turn structure calls it).

## Self-review notes

- **Spec coverage:** rules-core §704.5f (zero toughness) + §704.5g (lethal marked damage) → Task 2 predicate + Task 3 loop. §704.3 simultaneous-batch-then-fixpoint → Task 3 gather-then-perform loop, `batch_kills_multiple_in_one_pass` test. Conformance B2 (zero-toughness → graveyard) → Task 3 `minus_counters_to_zero_toughness_kills`. The "SBA reads CURRENT toughness" subtlety → Task 4 anthem test.
- **Reuse:** toughness via `characteristics()` (not printed); death via `move_object` (not hand-rolled). No P/T or zone-change logic duplicated in `sba.rs`/the loop.
- **Simultaneity:** Task 3 gathers the full doomed batch before performing any move (CR 704.3); documented in the impl NOTE. Borrow-checker-clean because gather (immutable) and perform (mutable) are separate phases.
- **Fixpoint termination:** each pass that performs a move strictly reduces battlefield creature count; a pass that finds nothing breaks. Cannot infinite-loop (no SBA in this slice creates a creature).
- **Composition + CoW:** Task 4 ties SBA to characteristics (computed toughness) and to fork isolation.
- **Type consistency:** `creature_dies_to_sba(&Chars, u32) -> bool` (Task 2) called in Task 3. `check_state_based_actions(&CardDb) -> Vec<MoveEvent>` (Task 3) used in Task 4. `marked_damage() -> u32` / `mark_damage(u32)` (Task 1) used in Tasks 3,4 and tests.
