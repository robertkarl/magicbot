# Static CardDb + minimal data-driven definitions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static `CardDb` of `CardDef`s (keyed on a stable def-id) that produces the layer-1 `BaseChars` and the static `ContinuousEffect`s that the layer system's `compute()` already consumes — turning the engine's inert `def_id: u32` into real printed characteristics for a tiny frozen card pool.

**Architecture:** A new module `magicbot-engine/src/carddb.rs`. A `CardDef` holds printed characteristics as data (name, mana value, types, colors, P/T, a small set of keyword abilities, and zero-or-more *static continuous* abilities expressed as data). `CardDb` is a `HashMap<DefId, CardDef>` loaded at startup (a hand-authored small pool here — no Scryfall/MTGJSON ingest yet). Two derivations bridge to the layer system: `CardDef::base_chars() -> BaseChars` (the printed layer-1 base) and `CardDef::static_effects() -> Vec<Effect>` (e.g. an anthem's "+1/+1 to other creatures" as `Effect::ModifyPt`). This is the static-data half; the executable effect IR (triggered/activated/replacement abilities, costs, targeting) is DEFERRED. `CardDb` is NOT part of the forked `GameState` — it's `&'static` shared data, consistent with the "behavior is static, state is flat" invariant.

**Tech Stack:** Rust 1.93+. `std::collections::HashMap` (CardDb is not forked, so a plain HashMap is correct here — persistent containers are only required on the fork path). No new deps.

**Source spec:** `prior-art/card-data-schema.md` (oracle_id as the stable key; what's structured vs free-text; the recommended CardDef fields) and `prior-art/REVISED-data-model.md` §1 (CardDb/CardDef/faces). Bridges to `magicbot-engine/src/layers.rs` (`BaseChars`, `Effect`, `Pt`, `TypeSet`, `ColorSet`, `Color`, `Ability`, `AbilitySet`).

## Global Constraints

- **Rust edition 2021**, toolchain `1.93+`.
- **CardDb is static, shared, NOT forked.** It must never be a field of `GameState`. A plain `HashMap`/`Vec` is correct here precisely because it is not on the copy-on-write path.
- **`DefId` is the stable "same card" key**, modeled on `oracle_id` (CR-research: reprint-invariant, name-collision-safe). A `u64` newtype.
- **Behavior is data, not code, for this slice's scope** — only *static continuous* abilities are modeled (anthems, animate-style type/P/T setting), expressed as the `layers::Effect` data the layer engine already consumes. Triggered/activated/replacement abilities, costs, targeting, the full keyword vocabulary: DEFERRED.
- **`base_chars()` and `static_effects()` must produce values the existing `layers::compute()` accepts unchanged** — this slice adds a producer, it does NOT modify the layer engine.
- **No Scryfall/MTGJSON network ingest.** The pool is a small hand-authored set in code (a `sample_pool()` builder). Real ingest is a later plan.
- **TDD**; `cargo test` + `cargo clippy --all-targets -- -D warnings` clean after every task.

#[derive(Copy, Clone, PartialEq, Eq, Hash, Debug)]
pub struct DefId(pub u64);

/// A single data-driven static continuous ability. Expressed as the layer
/// effect it produces; the layer engine (layers::compute) applies it.
#[derive(Clone, Debug)]
pub enum StaticAbility {
    /// "Other creatures you control get +power/+toughness." (Glorious Anthem.)
    AnthemOtherCreatures { power: i32, toughness: i32 },
}

/// Printed characteristics of a card, as data. Keyed on `def_id` (oracle_id).
#[derive(Clone, Debug)]
pub struct CardDef {
    def_id: DefId,
    name: String,
    mana_value: u8,
    types: TypeSet,
    colors: ColorSet,
    printed_pt: Option<Pt>,
    keywords: Vec<Ability>,
    statics: Vec<StaticAbility>,
}

impl CardDef {
    pub fn new(def_id: u64, name: &str, mana_value: u8) -> CardDef {
        CardDef {
            def_id: DefId(def_id),
            name: name.to_string(),
            mana_value,
            types: TypeSet::none(),
            colors: ColorSet::colorless(),
            printed_pt: None,
            keywords: Vec::new(),
            statics: Vec::new(),
        }
    }

    pub fn with_types(mut self, t: TypeSet) -> Self {
        self.types = t;
        self
    }
    pub fn with_colors(mut self, c: ColorSet) -> Self {
        self.colors = c;
        self
    }
    pub fn with_pt(mut self, power: i32, toughness: i32) -> Self {
        self.printed_pt = Some(Pt { power, toughness });
        self
    }
    pub fn with_keyword(mut self, a: Ability) -> Self {
        self.keywords.push(a);
        self
    }
    pub fn with_static(mut self, s: StaticAbility) -> Self {
        self.statics.push(s);
        self
    }

    pub fn def_id(&self) -> DefId {
        self.def_id
    }
    pub fn name(&self) -> &str {
        &self.name
    }
    pub fn mana_value(&self) -> u8 {
        self.mana_value
    }
}
```

use std::collections::HashMap;

/// The static card database. Shared, not forked — a plain HashMap is correct
/// because this is never on the GameState copy-on-write path.
#[derive(Clone, Debug)]
pub struct CardDb {
    defs: HashMap<DefId, CardDef>,
}

impl CardDb {
    pub fn new() -> Self {
        CardDb { defs: HashMap::new() }
    }
    pub fn insert(&mut self, def: CardDef) {
        self.defs.insert(def.def_id(), def);
    }
    pub fn get(&self, id: DefId) -> Option<&CardDef> {
        self.defs.get(&id)
    }
    pub fn len(&self) -> usize {
        self.defs.len()
    }
    pub fn is_empty(&self) -> bool {
        self.defs.is_empty()
    }
}

impl Default for CardDb {
    fn default() -> Self {
        Self::new()
    }
}

/// A small hand-authored frozen pool for engine bring-up. Real Scryfall/MTGJSON
/// ingest is a later plan.
pub fn sample_pool() -> CardDb {
    let mut db = CardDb::new();
    db.insert(
        CardDef::new(1, "Grizzly Bears", 2)
            .with_types(TypeSet::none().with_creature())
            .with_colors(ColorSet::colorless().with(Color::Green))
            .with_pt(2, 2),
    );
    db.insert(
        CardDef::new(2, "Serra Angel", 5)
            .with_types(TypeSet::none().with_creature())
            .with_colors(ColorSet::colorless().with(Color::White))
            .with_pt(4, 4)
            .with_keyword(Ability::Flying)
            .with_keyword(Ability::Vigilance),
    );
    db.insert(
        CardDef::new(3, "Glorious Anthem", 3)
            .with_types(TypeSet::none().with_enchantment())
            .with_colors(ColorSet::colorless().with(Color::White))
            .with_static(StaticAbility::AnthemOtherCreatures { power: 1, toughness: 1 }),
    );
    db.insert(
        CardDef::new(4, "Forest", 0).with_types(TypeSet::none().with_land()),
    );
    db.insert(
        CardDef::new(5, "Plains", 0).with_types(TypeSet::none().with_land()),
    );
    db
}
```

    pub fn static_effects(&self) -> Vec<crate::layers::Effect> {

// layer engine. Proves the producer (carddb) feeds the consumer (layers) correctly.
use magicbot_engine::carddb::{sample_pool, CardDef, DefId, StaticAbility};
use magicbot_engine::ids::Timestamp;
use magicbot_engine::layers::{compute, Ability, ContinuousEffect, Counters, Pt, Status};

#[test]
fn anthem_buffs_a_creature_through_the_layer_engine() {
    let db = sample_pool();

    // Grizzly Bears (def 1) is a 2/2.
    let bears = db.get(DefId(1)).expect("bears");
    let base = bears.base_chars();
    assert_eq!(base.pt, Some(Pt { power: 2, toughness: 2 }));

        .into_iter()
        .map(|e| ContinuousEffect { effect: e, timestamp: Timestamp(1), is_cda: false })

## Out of scope for this plan (deferred to later plans)

1. **Executable effect IR** — triggered/activated/replacement abilities, costs, targeting, modes, X. Only *static continuous* abilities (one variant, the anthem) are modeled.
2. **Affected-set scoping** — "other creatures you control" is produced as a bare `ModifyPt` body; which objects it applies to is the layer engine's job once wired into GameState. Not done here.
3. **Scryfall/MTGJSON ingest** — `sample_pool()` is hand-authored. Real data loading (oracle_id keying, type-line decomposition, multi-face `card_faces`) is a later plan.
4. **Multi-face cards** (split/MDFC/transform/adventure/room), tokens, meld — `CardDef` has a single face here.
5. **Mana cost parsing** — only an integer `mana_value`; the `{..}` symbol structure is deferred.
6. **Wiring CardDb into GameState** — `GameState` still holds an inert `def_id: u32`; a `GameState::characteristics(id)` that looks up the def, gathers active static effects, and calls `compute()` is the NEXT plan after this one.
7. **Full keyword/ability vocabulary and CDAs from game state** (e.g. Tarmogoyf).
