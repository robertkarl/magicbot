# Playable Demo Binary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A runnable `cargo run` demo that drives the engine through a scripted mini-game — cast creatures, bolt a creature, watch the priority loop resolve everything and an SBA kill the bolted creature — printing the board after each step. Proves the whole stack works together as a drivable program and exercises the public API as a consumer would.

**Architecture:** Two pieces. (1) A small read-only observation helper `GameState::battlefield_ids() -> Vec<ObjectId>` (in `state.rs`) so a driver can enumerate what's in play to render it — the engine currently has no way to list battlefield objects without already knowing their ids, which any consumer (demo today, AI later) needs. (2) A `src/main.rs` binary that builds a `GameState` + `sample_pool`, scripts a short sequence of `cast` / `pass_priority` calls, and prints a board summary (each permanent's name + current P/T via `characteristics`) after each resolution. No new engine rules — this is a consumer of the existing API, plus the one missing read helper.

**Tech Stack:** Rust 1.93+. No new deps (uses `println!`).

**Source spec:** the existing public API on `GameState` (`cast`, `pass_priority`, `characteristics`, `battlefield_len`, `get`) and `carddb::sample_pool`. This plan adds the one enumeration helper the API is missing and a binary that demonstrates the engine.

## Global Constraints

- **Rust edition 2021**, toolchain `1.93+`.
- **`battlefield_ids()` is read-only** and returns a `Vec<ObjectId>` of objects currently in `Zone::Battlefield`. Order is unspecified (im::HashMap iteration); the demo must not depend on order beyond rendering.
- **The demo adds NO engine rules** — it only consumes the public API. The only `src/` change to non-test code is `battlefield_ids()` and the new `main.rs`.
- **The demo is deterministic** — same script → same printed output (uses the seeded `GameState::new(2, 0)`; no randomness).
- **`cargo run` must work** and exit 0; the binary prints a readable trace of the mini-game.
- **TDD** for the `battlefield_ids` helper; the binary itself is verified by running it and asserting on a smoke test of its driver function.
- **`cargo test` + `cargo clippy --all-targets -- -D warnings` clean.**

```rust
    /// Every object id currently on the battlefield. Order is unspecified.
    /// A read-only observation helper for drivers (a demo, an AI's observe()).
    pub fn battlefield_ids(&self) -> Vec<ObjectId> {
        self.objects
            .iter()
            .filter(|(_, o)| o.zone() == crate::object::Zone::Battlefield)
            .map(|(id, _)| *id)
            .collect()
    }
```

### Task 2: The demo binary

**Files:**
- Create: `magicbot-engine/src/main.rs`
- Modify: `magicbot-engine/Cargo.toml` (add a `[[bin]]` entry)
- Test: a `#[cfg(test)]` smoke test inside `main.rs` for the driver function

**Interfaces:**
- Consumes: the public engine API (`GameState`, `carddb::sample_pool`, `PlayerId`, `Zone`, `characteristics`, `cast`, `pass_priority`, `battlefield_ids`).
- Produces:
  - `fn render_board(s: &GameState, db: &CardDb) -> String` — a readable multi-line summary: for each battlefield id, its card name and current P/T (from `characteristics`), one per line. Pure (returns a String) so it is unit-testable.
  - `fn run_demo() -> String` — scripts the mini-game and returns the full accumulated transcript (so a test can assert on it). Steps: P0 casts Grizzly Bears (def 1); resolve (both pass); P0 casts Serra Angel (def 2); resolve; P1 (opponent) now has a 2/2 from somewhere — actually keep it one-sided for determinism: P0 casts a creature controlled by P0, then P0 casts Lightning Bolt (def 7) targeting the Bears; resolve; run the priority loop again so the SBA kills the bolted Bears. Render the board after each resolution into the transcript.
  - `fn main()` — calls `run_demo()` and prints it.

- [ ] **Step 1: Write the failing smoke test**

Create `magicbot-engine/src/main.rs`:

```rust
//! A scripted demo driving the engine through a mini-game, to show the whole
//! stack working together. Run with `cargo run`.

use magicbot_engine::carddb::{sample_pool, CardDb};
use magicbot_engine::ids::PlayerId;
use magicbot_engine::layers::Pt;
use magicbot_engine::state::GameState;

/// Render the battlefield as a readable summary (one line per permanent).
fn render_board(s: &GameState, db: &CardDb) -> String {
    let mut lines: Vec<String> = s
        .battlefield_ids()
        .into_iter()
        .map(|id| {
            let chars = s.characteristics(id, db);
            let pt = match chars.and_then(|c| c.pt) {
                Some(Pt { power, toughness }) => format!("{power}/{toughness}"),
                None => "-".to_string(),
            };
            // def name via the object's def_id
            let name = s
                .get(id)
                .and_then(|o| db.get(magicbot_engine::carddb::DefId(o.def_id())))
                .map(|d| d.name().to_string())
                .unwrap_or_else(|| "?".to_string());
            format!("  {name} [{pt}]")
        })
        .collect();
    lines.sort(); // deterministic rendering despite unspecified id order
    if lines.is_empty() {
        "  (battlefield empty)".to_string()
    } else {
        lines.join("\n")
    }
}

/// Resolve the top of the stack: both players pass to let it resolve.
fn resolve(s: &mut GameState, db: &CardDb) {
    let _ = s.pass_priority(db);
    let _ = s.pass_priority(db);
}

/// Script a short one-sided mini-game and return the transcript.
fn run_demo() -> String {
    let db = sample_pool();
    let mut s = GameState::new(2, 0);
    let mut out = String::new();
    out.push_str("=== magicbot engine demo ===\n");

    // P0 casts Grizzly Bears (2/2).
    s.cast(1, PlayerId(0), None);
    resolve(&mut s, &db);
    out.push_str("\nAfter casting Grizzly Bears:\n");
    out.push_str(&render_board(&s, &db));
    out.push('\n');

    // P0 casts Serra Angel (4/4 flier).
    s.cast(2, PlayerId(0), None);
    resolve(&mut s, &db);
    out.push_str("\nAfter casting Serra Angel:\n");
    out.push_str(&render_board(&s, &db));
    out.push('\n');

    // Find the Bears on the battlefield (def_id 1) to bolt it.
    let bears = s
        .battlefield_ids()
        .into_iter()
        .find(|&id| s.get(id).map(|o| o.def_id()) == Some(1))
        .expect("bears on battlefield");

    // P0 casts Lightning Bolt (3 damage) at the Bears.
    s.cast(7, PlayerId(0), Some(bears));
    resolve(&mut s, &db);
    // Run the priority loop again so the SBA removes the lethally-damaged Bears.
    resolve(&mut s, &db);
    out.push_str("\nAfter Lightning Bolt kills the Bears:\n");
    out.push_str(&render_board(&s, &db));
    out.push('\n');

    out
}

fn main() {
    println!("{}", run_demo());
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn demo_runs_and_shows_the_expected_arc() {
        let t = run_demo();
        // Grizzly Bears appears after the first cast.
        assert!(t.contains("Grizzly Bears [2/2]"), "bears entered as 2/2");
        // Serra Angel appears as a 4/4.
        assert!(t.contains("Serra Angel [4/4]"), "serra entered as 4/4");
        // After the bolt + SBA, the Bears are gone but Serra remains.
        let final_section = t.rsplit("kills the Bears:").next().unwrap();
        assert!(final_section.contains("Serra Angel"), "serra survives");
        assert!(!final_section.contains("Grizzly Bears"), "bears died");
    }
}
```

## Out of scope for this plan (deferred)

1. **Interactive play / input** — the demo is scripted, not interactive. A REPL or AI driver is later.
2. **A real `observe(player)` API** — `battlefield_ids` is a minimal enumeration helper, not the hidden-info-filtered observation the AI will need.
3. **Turns/phases** — the demo drives priority directly; there is no turn structure.
4. **Two-sided play** — the script is one-sided (P0 casts everything) for determinism.
5. **Pretty/structured output** — plain text lines; no UI.
